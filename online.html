Online

The PS2 game was never designed for networking. Here is how we make it work, how to play and what is still missing.

How it works

Each player runs their own PCSX2 with the game. A small program next to the emulator (the client) reads and writes the game's memory through PINE, PCSX2's interface for external programs. The client talks to a TCP server.

PCSX2 + game ⇄ PINE ⇄ client ⇄ TCP ⇄ server ⇄ other clients

In each player's game, their own character (P1) is the only authority: feathers, unlocks and profile belong to them. The other players are "puppets": native game characters moved by the client with the data coming from the network, 30 times a second, with 100 ms of interpolation to keep them smooth.

When you join, the whole town map is preloaded, so everyone always has the same areas in memory. Traffic spawns from the same points with the same random generator, which is why people and vehicles match in every client.

How to play and host

Step by step, with launcher screenshots: Tutorial → Playing online. In short: Entra (Join) connects you to a server, Ospita e gioca (Host and play) creates one (TCP port 28022), and L1 + UP in game opens the online menu.

Game rules

  • Missions: whoever starts the mission is brought to the start first, then the others. If one player wins, everyone wins. During the mission, a player who strays too far or disconnects makes everyone lose.
  • Cutscenes and end screens: skipping or confirming counts for everyone. Saving is always skipped online.
  • Dropped feathers: they belong to whoever picks them up first, even if they were someone else's.
  • Vehicles: a vehicle is one and the same for everyone. If you take it, the others see you driving.

testing After leaving, the offline menu offers the last server again. A new Entra request releases the offline emulator connection before starting another online visit. It keeps profile saving and offline restoration, and reports the actual connection error. The launcher must stay running in the background. Reconnection steps.

Current limits

  • The game has 4 native player slots: with 5 or more, some buildings are not drawn. The server accepts up to 20 connections.
  • Several parts of the client still handle only one remote player. Work to reach 4 is under way.
  • The handlebars of scooters driven by other players don't turn.
  • Remote crocodile chase animation has a new correction under test. Restart the game with the updated source launcher; an older emulator state retains the old code. Test status.
  • Switching Bill / Aldo for remote players is being tested.
  • The Windows version hasn't been tested on a real Windows PC yet.
  • After a crash or a forced shutdown, restart PCSX2 before joining again.

Added rules — schema 14 testing

  • Campaign or Free Play in host options; switching to Free Play cancels an active attempt and keeps campaign progress. Switching back resumes the server's story.
  • Owned accessories stay separate from the temporary global grant; revoking it removes unowned worn pieces. Purchases remain in that server's profile.
  • Up to 64 persistent unlock/purchase points. Only the host places and removes them. Free pickup: within 1.1 m. Paid prompt: within 1.8 m, server range check within 2.4 m.
  • The server checks price, balance, range and ownership; the receipt and item are saved together. Revisions stop older autosaves undoing purchases or host edits. Feather earnings remain client simulated under the existing trust model.
  • L1 + Circle pushing on foot: target in front within 2 m, 0.8-second cooldown; the victim's owner simulates the fall and replicates it. Mounted or captured characters cannot be pushed.

Purchase confirmation uses the online menu and native renderer; the original shop window has not yet been reproduced and certified for all accessories. New models and reverse animation require visual testing. Feature status.

Proximity voice testing

L1 + DOWN toggles transmission; each connection starts muted. The server derives identity, range and volume from published player positions: full volume up to 2 m, fade to silence at 25 m, no self-echo. Each listener receives at most four nearest active speakers. Mouth motion uses speaking activity and only the character currently represented in the game; it does not add more visible player slots.

Mono PCM16 at 16 kHz travels in bounded 20 ms frames over the existing TCP connection, with sequence checks and rate limits. No extra port, service or audio recording file is introduced. Snapshots contain activity only. TCP loss can delay voice and gameplay; this first version has no separate UDP channel, echo cancellation, microphone selector or per-player mute. Headphones are recommended. Hardware/network quality and Windows await testing.
