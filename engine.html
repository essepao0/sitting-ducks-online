Game engine

What we found inside Sitting Ducks for PS2 and how we use it. Addresses refer to the European ELF SLES_521.16 (game v1.19); fields such as +0x334 are offsets inside the object.

Method and tools

  • Engine: Zouna by Asobo Studio, the same engine as other Asobo games of the period. Symbols were stripped from the ELF, but class names remain (PlayerMove_Z, VehiculeMove_Z…).
  • Ghidra with the Emotion Engine extension: 5,436 functions, all decompiled into one searchable file.
  • PINE from PCSX2 to read and write RAM live, with our own client.
  • RAM snapshots before and after an event (a feather picked up, a turn), compared to find the field that changes.
  • Python tools to read and rewrite .DPC/.DPS containers byte for byte, scale meshes and replace files in the ISO.

Memory and handles

  • gp = 0x0046F3F0.
  • Handle table: *(0x4680FC)+4, 16-byte entries [generation, refcount, pointer]. Handle = index<<8 | gen; 0x345070 resolves it, 0x251880 changes the refcount (at 0 the object is freed). verified
  • Free RAM for our code: 0x98000–0x200000, always zero in the original game.
  • Golden rule: never rewrite a 4 KB page holding code that has already run, or PCSX2's recompiler shuts down. New code goes into pages that have never run, and data into separate pages.

Pad input

Input_Z row verified: +1C Triangle, +1E X, +20 L3, +21 R3, +22/+25 up/down, +23/+24 right/left, +28 L1, +29 R1. Select can only be read from the raw pad at 0x476BC2, bit 1.

Vehicles and traffic

  • Global vehicle list: count *(0x467940)>>14, array *(0x467944). Object: +0x71 1 = player's, +0x78 type.
  • The traffic manager has 0x28-byte entries: +0xC owner, +0x24 in use. Clearing the owner stops the stolen vehicle from being recycled. verified
  • code — 23 October Native 0x3B4630 hides active entries belonging to a recycled civilian. The theft helper at 0xFFB00 now clears the vehicle's owner and reserves its entry immediately after ejection, before the player mounts. Tests execute the original recycling instructions against all three boot patches.
  • Recycling: after more than 2 s out of view (passer-by+0xBF0), in the loop at 0x3B2B00; passers-by spawn in 0x3B01A0.
  • Deterministic spawning: the same point and the same random generator state (0x46783C/0x478200) give the same passer-by. This is the basis of shared online traffic.
  • NOS: the vehicle's SPEED +B0/ACCEL +A0, fuel at +7C.

Animations

An animation id is translated into an Animation_Z through a hash map (0x268910); 0x3936A0 starts it. Each track holds a bone and rotation keys (12-bit quaternions). Tracks with a single key are fixed poses. Animations are shared by every character: to keep a single crocodile's mouth open we use a private copy.

code Remote chase, 22 October: state 24 (RunScary, 0x3A9100) selects clip 0x1E, then recalculates movement at 0x3A937C and writes playback speed through 0x393870 (PlayAnim+0x28). Neutral puppet input can reduce that speed to zero even with the correct clip selected. A live trace confirmed the correct clip with zero movement on the receiving client. The online movement hook now covers chase as well as walking and running. Native-call regression checks pass; visual confirmation in game is still pending.

World: fog, streaming, areas

  • Fog: HFog_Z +0xF8 = fog-free radius; with 2 players we raise it to 2000.
  • The graphics queue alternates two buffers per frame. With too many objects its tail overflows and VIF1 hangs: that was the co-op "freeze".
  • Closed areas: the barriers are objects hidden by CACHE_DECOR events; 0x2A5530 hides a node, 0x2A5640 shows it.
  • Sub-levels: REquestSubLevel fails if the area is already in memory. Online we keep it always loaded, so a guard fixes it (that was the black screen after the mission 12 cutscene).

Missions, cutscenes and menus

  • Cutscenes (RtcScripted_Z, update 0x3C8380) are skipped on the edge of a pad byte: we redirect it so a skip counts for everyone.
  • Mission end screens are menu pages (update 0x3EA6A0): results, failed (Retry/Continue), Save/Continue.
  • Moving away from the target fails the mission: the check is in 0x3D37A0.

Saves

16 KB block: data, a version byte at 0x3FFB (the European release expects 100) and a CRC32 at 0x3FFC computed by 0x251E70. US saves can be converted to European ones by changing the version and the CRC. verified

How we add code

Our MIPS code (written with a small Python assembler) gets into the game through PCSX2 PNACH patches, in free RAM. It hooks into chains of functions called every frame (the traffic update at 0x464DAC, the HUD at 0x464DF4), or replaces a vtable entry with a wrapper that calls the original. Each function has its own code page and its own data page.

code Packaging updates to the IOP audio protection now preserve later EE patches. Previously the updater truncated everything after its own marker. Regression checks cover the chase hook in the complete package.

Online missions, wardrobe and world items testing

Free Play blocks mission starts and filters the common marker query used by radar and map, leaving native arrays intact. The wardrobe uses allowed-choice masks per body zone; accessory IDs derive from resource names and remain separate from equipped choices.

The original shop routes object interaction into a native purchase menu. New offers use cloned graphic models without collectible agents: the server confirms the unlock and price before applying them. Removal detaches the model and releases the factory reference.

code and live memory · 23 October 2026 Native shop interaction at 0x3658A0 checks the name table at 0x4492F0/0x4492F4 and the ownership byte at GID+0x1C5C+item*0x24. Only a zero ownership byte reaches the menu opener 0x3D5CA0. The reported player already had every purchasable item in both memory and the server profile. No runtime code or ownership changed; a purchase with an unowned item still needs visual validation.

Pushing uses the native fall and physical velocity in the attacker's direction. Reverse playback sets the cursor to the clip duration and uses a negative speed. Code and automated tests cover these paths; in-game validation is still pending.

Maximum walking speed and speech layer testing

The speed correction wraps the native maximum-speed getter at 0x36AC60, multiplying its result separately for players and civilians. Native updates retain their original timestep; flight and mounted states are excluded. Changing the old timestep multiplier affected acceleration.

Speech fetches the native Talk clip without entering a dialogue state. Copies of the current animation replace only jaw rotations from Talk, using private buffers. The PlayAnim wrapper temporarily selects the copy for its update, restores the original clip afterwards and retains the existing crocodile callback. Body tracks, movement state and playback cursor stay intact. Incompatible clips and carrying poses skip the layer. Native HUD quads draw a microphone independently of the online menu.

L1 tap and combinations testing

The wardrobe tracks a pending tap per player and toggles only on release. Another button cancels the whole press, including through a mount/state change. L1+UP takes menu focus before arrow masking, without a wardrobe flash; L1+RIGHT drives the native character selector. The native push input wrapper forwards Circle unchanged unless L1 is also held. Controller shortcuts for clock switching and returning vehicles were removed; host options and ordinary interactions remain.

Single player and server settings testing

The NPC block retained return branches into older code that moved when a shortcut was removed: the main block and its helpers are now rebuilt together. The mission-marker query has seven EE arguments; the filter must preserve all of them, including icon output pointers. New checks execute words from the PNACH files and the original function body, so a helper rebuilt from source cannot hide a stale boot file.

The user confirmed that civilians and missions now work after the fresh start. The full host-option isolation test (flight, unlocks, accessories, speed and time after leaving) is still pending. The offline-fix suite passed 650 tests, one skipped. Use normal memory-card saves rather than older emulator states.
